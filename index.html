Dentro del modelo

Menos intuición.
Más alternativas visibles.

Una versión intencionalmente pequeña para entender un problema grande de asignación de recursos.

A

Primero, la viabilidad

Los perfiles deben cumplir cargo, experiencia y horas de ambas visitas. Una persona ocupa un solo cargo y no participa en reservas con fechas superpuestas.

B

Después, el puntaje

PPP = suma de (puntaje × horas asignadas) ÷ horas de los cargos puntuables. Los expertos son obligatorios, pero no aportan al numerador ni al denominador.

C

Luego, la decisión

Maximizar elige el mayor PPP. La meta elige el menor PPP que la cumple; puede dejar perfiles de mayor puntaje disponibles para otros escenarios.

Supuestos, alcance y privacidad

Modelo didáctico independiente. No representa las bases vigentes de ningún concurso ni valida propuestas ante la Contraloría. Los cargos, puntos, horas, fechas y reglas son ilustrativos. No es una herramienta oficial.

Combinaciones teóricas: producto de las combinaciones por cargo antes de comprobar disponibilidad, experiencia y duplicación entre cargos. Equipos viables: asignaciones completas que pasan todas las reglas de esta demo. Incluyen variaciones del experto; varios equipos pueden compartir el mismo PPP.

Reservas conservadoras: si dos visitas se cruzan, cada persona reservada queda bloqueada para el otro escenario completo. Las “unidades de experiencia” son un presupuesto ficticio que se descuenta por entidad, incluso si las fechas no coinciden. No implican que la experiencia profesional real se consuma.

Búsqueda exacta de alcance acotado: se recorren todas las asignaciones viables del conjunto sintético; las personas del mismo cargo se combinan sin contar permutaciones repetidas. No se modelan calendarios diarios, sustituciones, consorcios, documentación ni evaluación económica. No se garantiza el óptimo conjunto de una cartera: las reservas son decisiones sucesivas.

Privacidad: sin cuentas, cookies, analítica ni almacenamiento persistente. No se aceptan ni se cargan datos de trabajo. La aplicación no envía escenarios a un servidor; el proveedor de alojamiento puede registrar las peticiones web habituales. El archivo descargado contiene únicamente el escenario sintético.
